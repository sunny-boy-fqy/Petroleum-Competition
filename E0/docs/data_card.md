## 1. 两个会静默吃掉分数的硬发现

### 1.1 3 口训练井的表头不是官方 17 列

使用 `wc -l` + `csv` 逐井统计字段数后定位：

| 井（前 8 位） | 表头列数 | 多出的曲线 | 缺失的规范列 | 行数 | 所在折 |
|---|---:|---|---|---:|---:|
| `42f2870b` | 20 | `K, U, CGR` | `CASE` | 7,879 | fold 0 |
| `b7eb1274` | 21 | `TH, K, U, CGR` | `CASE` | 9,547 | fold 2 |
| `c7611b01` | 16 | — | `CASE` | 9,654 | fold 3 |
| **合计** | | | | **27,080（3.71%）** | |

- 这 3 口井的 **POR/PERM/SW 三目标齐全**，且**都在 `v1_well_folds.json` 的 80 井内**。
- 其余 77 口训练井与 10 口测试井 schema 完全一致（17 / 14 列）。
- 字段数分布（全部训练行）：17 列 703,188 行；20 列 7,879；21 列 9,547；16 列 9,654。总 730,268。

**结论（已冻结）**：解析必须**按表头名对齐**——建立 `列名→列号` 映射，逐行重排到规范 17 列；
规范列在本井缺失时填 `NaN`（记录 `missing_columns`）；本井多出的曲线忽略（记录 `extra_columns`，供未来使用）。

**踩坑记录（务必避免回归）**：开发过程中曾用 `arr[:, 15:18]` 取目标列，而当时内部数组只有 17 列，
numpy 对越界切片**静默截断**为 2 列，导致 **SW 整列被丢弃且不抛异常**，分数会直接掉约 23 分。
因此解析器末尾加入硬断言：

```python
assert arr.shape[1] == 17          # 规范宽度
assert targets.shape[1] == 3       # 目标必须 3 列
```

### 1.2 评分分母口径 = 逐目标排除缺测行（`drop`）

用常数基线 (POR=0.1, PERM=0.01, SW=99.9) 对 80 井全量打分：

| 分母口径 | 含义 | 复算值 | 与锚点 70.4907 |
|---|---|---:|---|
| `drop`（**冻结采用**） | 分母 = 该目标非缺测行数 | **70.490735** | 命中（±1e-4） |
| `mask`（诊断对照） | 分母 = 全部行，缺测行该目标得 0 | 69.843218 | 差 −0.6475 |

**结论**：官方 `N` 是**逐目标有效行数**。全项目 OOF 一律用 `drop`；
`src/constants.py::SCORE_MISSING_MODE = "drop"` 是唯一开关。

## 6. 对后续阶段的影响（必须遵守）

1. **E2 特征工程**：窗口统计与井级聚合必须建立在"按表头对齐后的规范 17 列"之上；
   对缺 `CASE` 的 3 口井，CASE 为 `NaN`，其缺失指示位为 1——这是**真实的可观测信号**（不同井的完井/井身信息不同），不得用平均值填补后当作正常值。
2. **E3 数据管线**：分片缓存（`cache/raw/*.npz`）必须存规范 17 列 + 逐列缺失指示，不再依赖原始 txt 的列位置。
3. **所有评分/比较**：`missing_mode="drop"`；任何报告若用 `mask` 必须并列两个数字并标注口径。
4. **契约测试是提交前置**：`predict.py` 生成结果后自动跑 `validate_payload`，不通过直接非零退出。
