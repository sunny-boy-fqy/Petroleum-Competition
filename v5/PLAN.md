# v5 冲分计划（2026-09-26 会话）

## 0. 环境与目标

- 资源：1× Ascend 910B (64 GiB HBM)、4000 vCPU、16 GB 内存、72 h 训练时间。
- 目标：B 榜总分 **> 83.5**（历史最好曾达 83.5），越高越好。
- 数据：`/root/v4rt/v4/data/{train,test}` = 80 训练井（730,268 行）+ 10 测试井（95,948 行）。
- 提交：代码 + `result.json` 推 GitHub `new` 分支；训练成果归档 `/data`。

## 1. 数据契约（E0，已实测复算）

| 事实 | 数值 |
|---|---|
| 联合占位行 (0.1, 0.01, 99.9) | 487,225 行 = 66.72% |
| POR 占位 / 有效 / 缺测 | 487,382 / 236,185 / 6,701 |
| PERM 占位 / 有效 / 缺测 | 494,598 / 228,959 / 6,711 |
| SW 占位 / 有效 / 缺测 | 518,255 / 205,302 / **51,917** |
| 有效 POR | min 0.0，中位 11.35，max 33.18 |
| 有效 PERM | min 0.011，中位 0.966，max 1064.7 |
| 有效 SW | min 8.305，中位 80.30，max 99.90（**百分数尺度，禁止裁到 [0,1]**） |

评分：`Total = (0.30·Acc_POR + 0.35·Acc_PERM + 0.35·Acc_SW)·100`，
POR/SW 为 8%/5% 相对误差线性截断，PERM 为 `1-|log10(ŷ/y)|`；缺测行按目标 mask 剔除（drop 口径）。

**恒等式（本项目全部策略的出发点）**

若逐目标占位检测完全正确：

```
Total = 70.45 + 0.0999·a_por + 0.1131·a_perm + 0.0826·a_sw
```

其中 `a_*` 为**有效行**上的准确率。常数基线 = 70.49（a_*≈0）。
故：① 占位检测必须接近完美（66.7% 的行是白送的分）；② 增益全部来自有效行的连续预测。
`a_por=a_perm=a_sw=0.45` → **83.75 分**。

## 2. 阶段计划

| 阶段 | 内容 | 产出 | 预算 |
|---|---|---|---|
| **P0** | 契约复算：常数基线、占位区间结构分析、oracle 上界 | `reports/P0_contract.json` | 1 h |
| **P1** | LightGBM 全链路基线（逐目标占位分类 + 有效行回归 + 硬切换解码），5 折井级 CV | OOF 总分基线 | 2 h |
| **P2** | NPU 深度序列模型：1D U-Net/TCN 特征主干 + 逐目标原子头 + 逐目标连续头，评分对齐损失 | OOF 提升 | 8 h |
| **P3** | 解码优化：温度校准 + 分桶期望分数决策（替代单阈值 τ） | +0.3~1.0 | 3 h |
| **P4** | 集成：多架构 × 多种子 + GBDT + 深度模型，先融合后硬切换 | +0.5~1.5 | 12 h |
| **P5** | 全量重训 + 测试集推理 + `result.json` 生成 | 提交包 | 3 h |
| **P6** | 复现校验（CPU 推理一致性）、打包、push GitHub、归档 /data | 交付 | 3 h |

## 3. 纪律

1. 长任务一律后台跑（`nohup`），日志落 `/data/v5/logs/`。
2. 每完成一个 P 立即 `git add -A && git commit && git push origin HEAD:new`。
3. 所有中间产物（OOF、权重、报告）落 `/data/v5/`，仓库只放代码 + 报告 + 权重小件。
4. 只用 python + pip；推理必须 CPU 可跑（复现要求）。
